### 📥 User Query

### 🛠 Changes Overview
**Scope:** `scripts/npm/build-packages.mjs`

**Key Actions:**
- **Root cause located**: Confirmed that after a global install, `/opt/homebrew/bin/open-computer-use` is a symlink, and the launcher computes the package root directly from `BASH_SOURCE[0]`, causing it to misidentify the package root as `/opt/homebrew`.
- **Fixed launcher template**: Made the `bin/open-computer-use` generated by the npm package resolve the symlink first before deriving `package_root`, making it compatible with Homebrew-style global npm bin paths.
- **Local hotfix**: Simultaneously patched the currently installed global launcher, and changed `~/.codex/config.toml` to the real script path, immediately restoring usability in the current environment.

### 🧠 Design Intent (Why)
The most common entry point for a global npm install is a symlink in the system bin directory. If the launcher can't correctly resolve the symlink, the package published to npm will simply fail at the default install path. This problem is more serious than a plain documentation issue — it must be fixed in the generation template, not just worked around via configuration.
