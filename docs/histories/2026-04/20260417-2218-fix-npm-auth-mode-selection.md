### 🧠 Design Intent (Why)

This round of debugging exposed two auth paths that interfere with each other:

1. When the npm CLI detects an OIDC environment inside GitHub Actions, it prefers to try Trusted Publishing first.
2. The package `repository.url` generated in the repo wasn't an exact enough match, which could cause Trusted Publishing's validation to fail.
3. Even after the workflow injects `NODE_AUTH_TOKEN`, npm won't necessarily actually take the token path unless the OIDC environment is explicitly blocked.

So this wasn't simply a matter of "add one more secret" — both the "package metadata" layer and the "auth mode selection" layer needed to be tightened, to keep the publish process from continuing to fall into the wrong auth branch.
