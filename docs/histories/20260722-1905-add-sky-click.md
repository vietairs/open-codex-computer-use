**Key Actions:**
- **SkyLight route**: Added a runtime `dlopen` / `dlsym` bridge, using `SLPSPostEventRecordTo` focus-without-raise, `SLEventPostToPid`, window-local event fields, an off-window Chromium primer, and a restore phase.
- **Safety boundary**: `sky_click` remains explicitly macOS-only, doesn't participate in `auto`, and has no fallback; it only accepts left-click single/double clicks on an on-screen window with the current PID, and serializes AppKit-active state transitions.

- **Attribution**: Pinned Cua / yabai reference commits, added MIT third-party notices, and documented private SPI compatibility.

### 🧠 Design Intent (Why)
*Chrome drops ordinary `CGEvent.postToPid` mouse events when occluded by another window. A full background-click path requires first switching only the AppKit event-routing active state while keeping WindowServer frontmost and z-order unchanged, then delivering a SkyLight event carrying Chromium telemetry and a primer; afterward, the AppKit state of whatever process is actually in the foreground is restored. This capability is high-risk and depends on a private ABI, so it stays explicit opt-in, fails closed, and is validated with a controlled Chrome page to confirm it fires exactly once with no foreground side effects.*
