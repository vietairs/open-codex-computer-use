## 3. Where each build script reads/writes the version

- `scripts/build-open-computer-use-app.sh:266` `read_package_version()` → `python3` parses `plugins/open-computer-use/.codex-plugin/plugin.json`, injects into generated `Info.plist` (`CFBundleShortVersionString`) at `scripts/build-open-computer-use-app.sh:326`.
- `scripts/build-open-computer-use-linux.sh:57` and `scripts/build-open-computer-use-windows.sh:57` — identical pattern: `node -e "console.log(require('./plugins/open-computer-use/.codex-plugin/plugin.json').version)"`, then `-ldflags "-s -w -X main.version=${version}"` (line 66 each) overrides the Go `main.version` var at link time. The `0.3.6-vietairs.1` literal at `apps/OpenComputerUseWindows/main.go:20` / `apps/OpenComputerUseLinux/main.go:23` is only the compile-time default when built directly with `go build` outside these scripts.
- `scripts/npm/build-packages.mjs:610` `main()` reads `pluginManifestPath` (same file), passes `version` through to `stagePackage`/`renderMetaPackageJson`/`renderReadme`/`renderPostinstall`. Nothing else hardcodes a version in that script.
- `scripts/release-package.sh` has no version logic of its own — it shells out to `build-packages.mjs` (which resolves the version) then `npm pack`s each staged dir and writes `release-manifest.json` (git SHA + artifact list only, no version field).

## 4. `validate-github-release-notes.mjs` — what it expects

- Takes `--tag vX.Y.Z`, parses semver via `tagPattern` (`scripts/validate-github-release-notes.mjs:12`).
- Unless `--notes-only`, reads `plugin.json` and **fails the run if `manifest.version !== version`** (derived from the tag) — `scripts/validate-github-release-notes.mjs:133-137`. This is the actual cross-check enforcing tag ↔ manifest consistency; it's wired into `.github/workflows/release.yml:42` (`RELEASE_TAG` = the pushed git tag).
- Also validates `docs/releases/github/<tag>.md`: must start with `## What's Changed`, 1-3 bullet items, exactly one `**Full Changelog**: <repo>/compare/<prev>...<tag>` line, no CJK characters, trailing newline.
- `repositoryURL` (used in the Full Changelog line) is derived from `git remote get-url origin` when possible (`resolveRepositoryURL()`, lines 15-34), falling back to the upstream slug `https://github.com/iFurySt/open-codex-computer-use` only when no origin remote is configured — so on this fork (origin=vietairs/...) it correctly resolves to the fork's own compare URL at runtime, not the hardcoded fallback.
