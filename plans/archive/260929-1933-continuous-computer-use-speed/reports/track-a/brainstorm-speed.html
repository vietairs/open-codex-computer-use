Speed Design Options

Track A (PR A: speed). Scope is locked by outcome-lock decisions 1-6 and 11; options differ only in how each is built. Source read at HEAD afb60fa, read-only. Mail step: ~9s total, server share ~3-3.5s (cursor travel 1.43s, pulse 0.16s, settle 0.15s, post-action refresh 1.4-1.6s).

Challenged assumptions

Pre-action snapshot is already free

The cache has no freshness check; waste is the post-action refresh. No TTL, no code change, one confirming measurement.

Cursor is the biggest server cost

1.43s fixed travel per click. Capture is likely 0.1-0.5s (not measured); screenshot cost is mostly agent-side (290-356 KB).

Skipping capture breaks x/y clicks

No PNG means scale falls back to 1x1. Carry the coordinate frame forward or fail closed.

jev disk cache may never fill

22 of 27 sequential /tokenize calls hit the 12s deadline under GPU load. Open question 2.

Proposals

Recommended

A: thin batch runner + observation policy

  • Validate every step first; pinned snapshot passed to each step; one final text state.
  • Capture policy always | never | whenTreeEmpty; text-only by default.
  • ~450 LOC; closure seam for tests without live AX.
  • Cursor travel capped ~0.3s; settle sleeps into one constant.

Risk: medium. Click ~1.9s (-40%); 3-step batch ~2.1s, 1 turn.

Medium-high risk

B: perform/observe split

  • Move ~365 LOC of action bodies into performStep; each single action is a batch of one.
  • Strong DRY and test coverage; moves a 2074-line file toward modularity.
  • Turns a speed PR into a refactor PR; all-or-nothing rollback.

~900 LOC. Same speed as A. Suggested as optional follow-up.

High risk

C: state on demand

  • Actions return an ack; full state only with return_state.
  • Largest win: single action ~0.5s (-85%).
  • Changes the action-result contract; extra get_app_state turns; stale indices; stretches decision 3.

~550 LOC. Turns criterion at risk.

Rejected

D: reuse --calls over MCP

  • ~30 LOC, full reuse of the CLI runner.
  • Every step refreshes: 3 AX walks (~4.5s+).
  • Indices renumber between steps, so step 2+ can click the wrong element; returns N states.

Fails index resolution and decision 1.

Recommendation

Proposal A, borrowing two ideas from B: validate all steps before any runs, and pass the pinned snapshot explicitly to each step.

  • Meets decisions 1-6 and 11 with the smallest blast radius in the most fragile file.
  • Keeps the single-action contract; tests batch semantics without the fixture app.
  • Leaves B's refactor as an optional follow-up after PR A's measurements.
  • C bends decision 3 and costs turns; D is incorrect.

Shared component choices

Cursor travel

Pick (a): cap blocking travel ~0.3s (spring already time-scaled), about -1.1s per click. Reject non-blocking travel (main thread still busy). Baseline via OPEN_COMPUTER_USE_VISUAL_CURSOR=0.

Fixed sleeps

Lowest-value lever (max 0.15s, ~5%). One postActionSettleInterval constant, measured alone. Keep settle between batch steps.

jev letter disk cache

Per-key file sha256(base_url|model).json, 0600 in a 0700 dir, atomic rename, no api_key, prompt-hash invalidation, any read failure is a miss.
