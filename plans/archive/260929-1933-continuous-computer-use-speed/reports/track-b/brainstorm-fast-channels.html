Fast Channels Brainstorm

Track B, PR B: run_script, sdef lookup, find_elements, Shortcuts/URL launcher, plus script-first guidance (outcome-lock decisions 7–10). The proposals differ only in how they are built.

Key facts from source

  • The default-install “MCP server process” is only a relay; the app agent runs the real StdioMCPServer. Adding run_script to the Kit dispatcher would run it in the agent and break decision 8.
  • call run_script is a second route into the agent (kind:"cli"); the scripting flag would also leak via sanitizePeerEnvironment.
  • Apple Events from the relay or its children use the host’s responsible app for Automation TCC (terminal, Claude.app, Codex.app), not OCU.app.
  • Signed builds use hardened runtime without entitlements; in-process Apple Events work only in ad-hoc dev builds.
  • Measured: osascript spawn 0.04–0.17s; /usr/bin/sdef 1.67s; reading the bundle .sdef about 0s.

Proposals

Risk: high

P1: In-process OSAKit in the relay

  • Router in relay answers script tools locally; NSAppleScript / OSAScript on main thread.
  • find_elements = predicate mode + early stop in existing TreeRenderer.
  • Needs apple-events entitlement, build-script and Info.plist changes.

Pros: exact wording of decision 8; no spawn; indices identical to get_app_state.

Cons: no cancellation, a hung script wedges the relay; JXA ObjC bridge in the server; entitlement also lands on the agent; 15–25 AX reads per node stay; clashes with Track A in AccessibilitySnapshot.swift.

Effort ~3.5 days, ~1.1k LOC.

Recommended Risk: high, lowest of three

P2: Relay-local router, osascript child, lean walker

  • Same router topology; never linked into the agent server.
  • /usr/bin/osascript child: stdin source, scrubbed env, 20s default / 60s max timeout, SIGTERM then SIGKILL, 64 KB caps.
  • sdef: read bundle .sdef file, XInclude resolved, summarised; no subprocess.
  • Launcher: NSWorkspace.open with scheme policy; /usr/bin/shortcuts.
  • find_elements: lean DFS with one multi-attribute AX read per node, early stop, indices ≥ 10000 merged into cached snapshot.
  • Audit log to stderr and 0600 scripts.log; normalising deny filter.

Pros: hung scripts are killed; no entitlement; dev and release behave the same; ~10–20x fewer AX calls per node; Track A action path untouched.

Cons: 40–170 ms spawn; stretches decision 8 wording (Q1); second index range to document.

Effort ~2.5–3 days, ~1.0k LOC.

Risk: high + release risk

P3: Separate scripting MCP server

  • New mcp-scripting subcommand never proxied to the agent (structural guarantee).
  • Uses the P2 child runner; find_elements stays in the main server.
  • Second server registered via --with-scripting.

Pros: cleanest separation; human review by default (separate allow rule); independent uninstall.

Cons: touches ~6 installers, npm packaging, plugin manifest; split guidance weakens decision 9; two relays per session; ~1.3s per-call review; shared StdioMCPServer refactor with Track A.

Effort ~4–5 days, ~1.3k LOC + installers.

Recommendation

P2. It meets every PR B acceptance criterion with the highest confidence, including find_elements at ≤50% of get_app_state. It is the only in-server option that contains hung or looping scripts, adds no entitlement to the TCC-holding agent, and touches Track A files only in append-only regions. It needs no signing or installer change.

If the main loop rules that an osascript child violates decision 8’s wording (Q1), keep P2’s topology and swap only the engine to P1’s in-process OSAKit, accepting the entitlement and the no-cancellation gap. Do not take P1’s predicate-renderer find_elements.
